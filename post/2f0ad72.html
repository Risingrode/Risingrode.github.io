套利规划

发表于2025-07-08|更新于2026-10-01
|字数总计:1.8k|阅读时长:6分钟|阅读量:

规划

未完成的

  • 慢 blockhash 策略 tpu 策略
  • 要求 account 构建没有问题
  • 全局变量 arc 化 这个适合只读情况
  • 汇率计算不规则现象 只需要在合约里面计算 pamm 购买的汇率即可
  • grpc_account 不要引起线程阻塞 CPU 没有打满 还需要加速优化
  • 合约的 pamm 买入不支持 0 滑点 卖出支持 需要把计算代码写到合约里面
  • 合约测试成功
    • 合约每一个需要实验一下 看看如何更省 CU
    • 在开发网上面再次测试一下合约
    • 测试合约调优　把该删掉的日志都删掉
  • 交易构建成功
  • set_token_data 可以直接移除 不需要了
  • 实时价格计算，redis 可以移除了
  • 添加定时器获取 blockhash
  • 需要优化的点
    • entry 那里需要 public 写死
    • 获取数据的时候使用 get_mut

三个大点

  • 合约
  • grpc_account 用于构建基础数据
  • grpc 用于解析各种数据
  • 指令构建

学习这笔交易：https://solscan.io/tx/2732JbtzCqZnqoZHwcaNHfa2nKyWsspaYvwnVtba1ZSJh1YJsF6nst3BDmoSE9ucgJ3xn5YTuYXeFNBvoN51pjv7

去除警告运行命令：RUSTFLAGS = “-Awarnings” cargo run –bin arb

总体任务计划

  • 指令拼接

    • pamm buy 需要链上计算汇率 sell 不需要
    • raydium amm 卖和买 ata 交换一下位置即可 重复的 market 地址不需要是 writeable 合约那里似乎写错了
    • raydium cpmm // 卖出的时候 要有三对进行替换 ata vault mint
    • meteora damm 卖和买 ata 交换一下位置即可
    • solfi 最后一位，0 是 buy 1 是 sell 看来要改一下合约了 其他的不需要改
    • raydium clmm 写死使用 swap v2 尝试 swap 交易 token 和 ata 和 pool1 这三个地址对进行换位置 data 的 bool 始终保持为 true
    • meteora dlmm 他的 tick 要求严格具有一定的时效性
    • meteora pool 买和卖的 fee 账户不一样 注意还有最后一位可有可无的 这个太特殊了 后面要改
      • mSol 这个比较特殊 数据库那里需要打上标记啥的
    • linfity 买卖的时候 swap_source 和 swap_destination 要换一下位置 ata 也换位 就 ok 了
    • orca 售卖的话 aTob 参数修改成 false tick 换成 对应的 sell tick
    • 完善文档添加对比交易

  • grpc 数据流

    • 保持不断开　不断开的前提是可以解析所有事件
    • 保持持续开 2 条数据流　就开一条吧　２ 条容易阻塞

  • tick 如何存储 7dg 的 tick 后面跟了 5 个

    • grpc 抓别人的 或者 account 流自己算

  • 每一个 dex 添加对应条件 并且设置 j++ 以便快速过滤

  • flash 的 usdc

  • 尝试单开监听池子数据流计算 tick - 这个目前算了，因为单开一个没啥用处

  • 把 redis 数据转化成全局变量包 - 全内存快照

  • 交易过滤那里再添加一个双签名 把这种交易不要了

  • grpc_account 那里的 orca 池子需要筛选 不然老是断开

  • grpc_account 精细化 ata 啥的也需要全局变量精细化处理

  • 提升 redis 速度 只能全局话处理

  • token 数据库 可能需要引入价格 进而执行路由操作 还有方向控制啥的

    • 计算汇率 也就是价格 只计算 sol- token 之间的汇率 然后就是发现交易 直接从池子里面找到 最大的和最小的汇率 但是关键点是判断汇率方向

  • linfity 需要精确识别数据 按照 swap 前缀去识别

  • 数据库精细化处理 数据之间的 token 如何进行对应啥的

  • entry 序列化标志

  • base58 优化

  • 代码格式化 cargo fmt

  • 开 2 个 grpc 数据流

  • 每一个 池子搞一下基础 CU 设置

    • klend - usdc 7.7w

    • klend - wsol 6.7w

    • solfi 49123

    • solfi jito setdata 7w CU -setdata 可以不要

    • pamm 7.7 w

    • orca 4.5 w

    • lifinity 6.5 w

    • meteora_pool 15w

    • meteora_dlmm 5.5w

    • meteora_damm 4w

    • raydium 2.5w

    • raydium_clmm 7.7w

    • raydium_cpmm 4w

  • 交易发送的代码

    • jito
    • astra
    • tpu
    • 预估下一块　数据库里面打上时间戳啥的

  • 哪一种 base58 速度更快　不行的话就使用 asm - 暂且使用那个老点的
